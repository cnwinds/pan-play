# 0007 一款游戏可以有几种格式，exFAT 镜像在 PS5 上读写挂载

状态：已接受（2026-10-24）

## 背景

很多文件夹版游戏在主机上玩不了，比较可能的原因是文件名大小写：内置盘上的文件夹区分大小写，exFAT 不区分，资源里大小写写错的文件在文件夹版里就找不到。论坛上反馈同一款游戏换 exFAT 镜像版能玩。

资源站同一个帖子常常同时给 exFAT 和文件夹两份（盘架统计约 320 个）。exFAT 资源也是分卷 RAR，解压出来是一个几十 GB 的 `.exfat` 镜像文件，旁边通常带一个固件补丁（backport）。站上标的 fpkg 是自制 PKG 安装包，不是 ShadowMountPlus 的 ffpkg（UFS 镜像）；ffpkg、ffpfs 站上都没有。

原来盘游把游戏目录里的压缩包全部叠成一个游戏，两种格式放在一起会被当成"游戏 + 补丁"叠坏；装完只认带 `sce_sys` 的文件夹，镜像文件注册不了。

## 决定

### 网盘目录：一种格式一个 `@格式` 子目录

```
<游戏库目录>/
└── 极速骑行5 PPSA15190/
    ├── @exfat/          exFAT 镜像版：分卷 RAR + backport
    ├── @folder/         文件夹版
    └── @other/          资源站没标格式的
```

- 名字是 `@` 加小写字母或数字，格式就是去掉 `@` 的部分。盘架按格式转存时就放成这样（`<转存目录>/<编号>/@exfat|@folder|@other`）。
- 每个 `@格式` 目录是一个**变体**，安装、评价、有没有更新都按变体目录走，变体目录下面照旧可以有补丁子目录。
- 游戏目录本身不再收 `@格式` 目录里的压缩包。游戏目录里另外直接放着压缩包时，它也算一个变体（没分格式），排在最后。没有 `@格式` 目录的旧游戏不受影响。
- 详情页列出各个变体让用户选，优先选已装的那个，没装时选第一个（exfat、folder、其他的顺序）。

### 主机上：同一款游戏只装一种格式

- 各个变体都装到同一个文件夹（游戏目录名里的 Title ID），完成标记 `.panplay-done.json` 里记 `variant`。
- 已经装了一种格式时，安装别的格式直接拒绝、不能重试，提示先删除已装的；详情页显示「主机上装的是 X 版」，不显示有更新。完成标记里没有 `variant` 的（旧版本装的）、`variant` 为空的（从没分格式的游戏目录装的）算哪种都对得上：盘架把旧目录迁进 `@格式` 子目录后，压缩包没变就仍是已安装，不用重装；打开别的格式会显示有更新，装的话整个换成那种格式。
- 删除已装的游戏从哪个变体点都行，删的是同一个文件夹。

### 镜像的安装：照旧解压，零块稀疏写

镜像版走原来的安装流程：解压出来的 `.exfat` 就是游戏文件夹里的一个文件，backport 解压到它旁边。镜像里大段是空的，写入时整块（4 MB）全零的就跳过不写，文件结尾是空洞时最后补到原来的大小，省掉一大半写盘时间。

已知限制：续装按文件算，一个上百 GB 的镜像中途断了要从头解这个文件。

### PS5 上：LVD 读写挂载，backport 写进镜像

游戏文件夹第一层只有一个 `.exfat`（或 `.ffpkg`）时算镜像版。注册、开机恢复时：

1. 打开 `/dev/lvdctl`，用 attach ioctl（`0xC0286D00`）把镜像挂成 `/dev/lvdN`。参数照 ShadowMountPlus（`include/sm_mount_defs.h`、`src/sm_image.c`），但按读写挂：
   - exFAT：扇区 512、`secondary_unit` 0x10000、flags 0x14、`image_type` 0；`nmount` 用 `fstype=exfatfs`、`budgetid=game`、`large=yes`、`timezone=static`、`async`、`noatime`、`ignoreacl`。
   - ffpkg：扇区 4096、`secondary_unit` 4096、flags 0x16、`image_type` 7；`fstype=ufs`，`nmount` 的 flags 是 `0x10000000`。
2. 挂到 `/mnt/panplay/<游戏文件夹名>`。镜像根目录有 `sce_sys/param.json` 就用根目录，否则用根目录下唯一带它的子目录。
3. 把游戏文件夹里镜像以外的文件（backport、补丁）按原路径写进镜像里的游戏目录，写完在游戏文件夹里记 `.panplay-overlay`（内容是镜像文件的设备号、inode、大小加上当时的完成标记），都没变就不再写。装了更新后完成标记变了，下次挂载会重新写。
   - 整个重装时新镜像先写进暂存区再改名替换，旧镜像还被 LVD 挂着。挂载时在 `/mnt/panplay/<游戏文件夹名>.image` 记下挂的是哪个镜像文件，注册时发现对不上，就先卸掉 `/system_ex/app/<ID>` 的 nullfs 和旧镜像，再挂新镜像、重新写入 backport；旧镜像卸掉后空间才腾得出来。游戏正在运行时卸不掉，注册报错，关掉游戏后重新注册。
4. 之后和文件夹版一样（ADR 0003）：镜像里的游戏目录 nullfs 挂到 `/system_ex/app/<ID>`，`mount.lnk` 指向它，再调注册接口。另外写 `/user/app/<ID>/panplay.image` 记下游戏文件夹，开机恢复时先挂镜像。
5. 删除时先按 ADR 0003 注销、卸 nullfs，再卸掉镜像挂载、detach `/dev/lvdN`（ioctl `0xC0286D01`），之后才能删镜像文件。游戏在运行时卸不掉，照样提示先关游戏。

镜像里文件的权限由挂载决定，镜像版不补权限、不检查 `eboot.bin` 的执行位。

ShadowMountPlus 在运行时，盘游不挂镜像：两边同时读写挂同一个镜像会把镜像写坏。

### 评价带上格式

评价记录加 `format` 字段：`exfat`、`folder`，其他格式和没分格式的记 `unknown`，和盘架那边的取值一致。评价仍按压缩包内容认（ADR 0004），格式只用来显示和区分。

## 不做

- ffpfs（PFS 镜像）：要处理加密和签名，站上也没有这种资源。
- 只读挂载、backport 用 nullfs 叠在镜像上面：exFAT 不区分大小写，叠一层区分大小写的目录又会把大小写问题带回来；写进镜像最简单。
- 同一款游戏同时装两种格式。

## 影响

- 镜像是读写挂的，backport 写进去后镜像就不是资源站原样了；删掉重装才能回到原样。
- 盘架和盘游要一起改：盘架负责按格式转存、迁移旧目录，盘游负责识别 `@格式` 目录。
- 读写挂载参数、`budgetid` 在各固件上是否都可用，要实机验证。
