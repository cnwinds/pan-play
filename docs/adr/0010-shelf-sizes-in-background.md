# 0010 游戏库封面上的容量由后台量好存起来

状态：已接受（2026-11-02）

## 背景

封面右上角平时显示游戏大小、装在主机上的标绿底（界面在 2026-10-31 改的）。但游戏库列表只列游戏库一级目录，看不到每个游戏目录里的压缩包，列表接口里的容量一直是 0：只有打开过详情的游戏，页面把详情读到的容量抄到格子上才显示，刷新页面就又没了。详情缓存（`game-details.json`）里其实存着容量，列表也没用。

要每张封面都有容量，就得把每个游戏目录列一遍（有补丁子目录、按格式分了的还要多列几次）。游戏库通常几十到几百款，打开页面时同步列完要几十秒，不能放在列表请求里。

## 决定

- 新增容量缓存 `game-sizes.json`（`pc/src/game_sizes.cpp`），按网盘路径记压缩包总大小和量的时间。key 是网盘和游戏库目录，和存放位置无关；换了就全部重新量。
- 列表每次重新列过网盘目录（首次打开、页面要求刷新、改了设置）就把游戏目录交给后台线程：没量过的、量过超过一天的逐个去量，已经不在网盘上的记录删掉。一款一款来，每款之间歇 0.3 秒，免得百度列目录接口限流；连着三次出错就停下，5 分钟后整轮再来，量过的跳过。
- 量一款游戏用 `measure_game`：列一次游戏目录，再列各补丁子目录；按格式分了的，每个 `@格式` 目录各量一份（见 [0007](0007-game-format-variants.md)）。只列目录，不读文件内容。
- 量到新的容量就让游戏库版本号加一（连着量时最多三秒一次），开着的页面照常重取列表，封面一批一批补上。
- 打开详情时实时读到的容量也写进这份缓存，网盘上加了补丁后看过详情，封面马上跟着变。
- 分了格式的游戏，封面显示主机上装着的那种（详情读到过才知道）；没装时显示详情默认打开的那种（文件夹、exFAT、其他的顺序）。

## 影响

- 打开游戏库后后台会持续调网盘的列目录接口，每款游戏 1～4 次，之后一天一轮。
- 评价角标仍按 [0004](0004-game-reviews.md) 只用详情缓存里的指纹，后台量容量时不顺便算指纹。
- 在别处往网盘加了补丁、没打开详情时，封面上的容量最多晚一天才更新。
