# 0012 盘架用大模型编排安装方式，盘游照编排装，有问题经网盘反馈

状态：已接受（2026-11-12）

## 背景

资源站的分享五花八门：主游戏分卷可能被拆在几个目录里，补丁有的是压缩包、有的就是单独的文件，有的附一份说明，要求把某个文件拷进游戏的 `fakelib` 覆盖原文件（PPSA03016：`apr0.4.2.1/libSceAmpr.sprx`）。盘游原来只按固定规则猜：游戏目录里最大的那组压缩包是主游戏，子目录里的是补丁，压缩包以外的文件一律不管。猜错了装出来的游戏起不来，而且没人知道。

说明是写给人看的自然语言，规则写不全；大模型读得懂。分析在盘架上做（电脑上、离线、不赶时间），结果写进资源库（[0011](0011-install-from-catalog.md)），盘游照着装。

## 决定

### 盘架：分析一条链接

- 输入：分享的全部文件（去掉唯一外包目录后的相对路径、大小、md5），分享里的说明文件内容，帖子标题和这条链接的备注，以及（重新分析时）盘游反馈的问题。
- 说明文件：分享里 `txt`、`md`、`nfo`、`url`、`ini`、`json`、`htm` 这类、256 KB 以内的，最多 10 个，只把它们转存到网盘的 `/盘游/临时/<surl>`，读完就删，不占游戏空间。UTF-8 读不通按 GBK 读。
- 文件按序号列给模型，模型只回序号，不回路径：主游戏是哪几个、补丁按顺序是哪几组、哪些单独的文件要放到游戏目录的什么位置、有哪些盘游做不了的步骤要提醒。盘架核对：序号都在、主游戏和补丁都是压缩包、目标路径是游戏目录里的相对路径（不能有 `..`、不能以 `/` 开头）。核对不过把原因告诉模型再来一次，还不过就记为分析失败，这条链接不带编排。
- 模型用 OpenAI 兼容接口（`/chat/completions`，要求返回 JSON），在盘架设置里填地址、密钥和模型名；没填时不分析，盘游照旧按规则装。
- 一条链接一份编排，存在 `link_plans` 表，`rev` 每次重新分析加一。分享内容的指纹（全部文件的路径、大小、md5）也记下：链接检查（0011）列出来的分享变了，就重新分析。

### 编排放在哪

资源库只放摘要，完整的编排一条链接一个文件，盘游装的时候才去取（2026-11-12 起，资源库 `version` 2）。全放在资源库里时，1500 种格式的分卷清单让资源库从 0.5 MB 涨到 1.7 MB，盘游每次解析要 16 MB，盘架发布得勤时正好撞上装大字典的游戏；只放摘要后解析约 5 MB。

资源库里每种格式的 `plan`（分析失败或没分析时不写）：

```json
"plan":{"rev":2,"size":128849018880,"layers":["主游戏","降级补丁 4.xx"],"copies":1,"notes":["要用 ShadowMountPlus 1.7alpha12 或以上挂载"]}
```

完整的在 `/盘游/编排/<游戏编号>/<surl>.json`。盘架先传完整的、确认传上去了才在资源库里写摘要；盘游按 `rev` 核对，取到的缓存在数据目录 `shelf-plans/`，同一版不再下载。资源库里的 `plan` 本身带着 `layers` 文件清单时（`version` 1）照旧直接用。

完整编排的内容：

```json
{"rev":2,"model":"deepseek-chat","at":1794470400,"size":128849018880,
  "layers":[{"role":"main","name":"主游戏","files":[{"path":"PPSA03016-app.part01.rar","size":4294967296,"md5":"…"}]},
            {"role":"patch","name":"v1.05 补丁","files":[…]}],
  "copies":[{"from":{"path":"apr0.4.2.1/libSceAmpr.sprx","size":423350,"md5":"…"},"to":"fakelib/libSceAmpr.sprx"}],
  "packages":[{"path":"DLC/Split.Fiction.Crack.PS5-DUPLEX.pkg","size":1320845,"md5":"…"}],
  "notes":["主机的 /data/shadowmount/emus/ 也要放一份 libSceAmpr.sprx","要用 ShadowMountPlus 1.7alpha12 或以上挂载"]}
```

资源库摘要里 `packages` 是个数，没有时不写。

`notes` 只写用户必须在主机上亲手做的步骤；编排里已经处理了的、对资源本身的描述不写。

- `layers` 按叠放顺序，第一层是主游戏。`files` 是一组压缩包的全部分卷，按卷序。
- `copies` 只能放进这款游戏的安装目录里（相对游戏根目录）。说明里要求往主机别处放文件、换挂载工具的，写进 `notes` 给用户看，盘游不做。
- `packages` 是要在主机上安装才生效的小 PKG：激活完整版、解锁 DLC 的授权包（比如双影奇境的 `UP0006-PPSA08560_00-FULLGAMEUNLOCK00`，类型 `PS5AC`，1.3 MB，里面没有游戏文件，装上后系统记下这条附加内容，游戏查到就当完整版）。这种包解开放进游戏目录没用，只能走主机的安装接口。盘架只收 32 MB 以内的 `.pkg`，整款游戏、补丁的 PKG 不收。
- 2026-11 之前排的编排没有 `packages`；分享里有 32 MB 以内 `.pkg` 的，盘架启动时排上重新分析。
- `size` 是分享里全部文件的大小，也就是下载要多大。

### 盘游：照编排装

- 安装前按 `md5` 和大小在网盘的这个格式目录里（往下三层）找编排里的每个文件，`md5` 没有时按相对路径和大小。只要找得到就行，放在哪个子目录不要紧：转存时外包目录没挪干净的也能装。
- 找齐了：只装编排里的压缩包组、按编排的顺序叠；装完把 `copies` 的文件写进游戏目录，同名的覆盖压缩包里的。不在编排里的压缩包不装。
- 找不齐：自动反馈给盘架（「对不上」），这次照旧按规则装。
- 详情页列出压缩包组、判断有没有更新也按编排。~~有 `notes` 时在详情页显示「盘架说明」~~ → 2026-11-13 起不显示 `notes`：实际出现的是「DLC 包要在主机上另装」（盘游会自动装激活包）、「backport 面向 4.xx 固件」（backport 照常叠进游戏目录，启动时自动挂 fakelib）、「帖内另附 fpkg 链接」这类，用户什么都不用做，显示出来只会让人以为要手动处理。
- `packages`：主机上的盘游装好游戏、注册到主机后，把每个包下载到数据目录 `packages/`，核对是 PS5 的 PKG（`\x7FFIH` 开头）、包配置里类型是 `PS5AC`、内容 ID 里有这款游戏的编号，再换成 ShellCore 的进程身份调 `sceAppInstUtilInstallByPackage`（安装服务在沙盒里只看得到 `/user/data`，`/data/...` 的路径要改写成 `/user/data/...` 传裸路径，否则回 `0x80b2150f`），按 `sceAppInstUtilGetInstallStatus` 等到 `playable`，删掉下载的文件。做法照 etaHEN 的「PS5 Package Installation」说明。系统回「附加内容已经装过」也算装好。结果按包的 md5 记在数据目录 `console-packages.json`，装好的不再装；详情页「要在主机上安装的包」列出每个包装好没有、没装上的原因。已装好的游戏还有包没装好时显示有更新，点更新会补装（游戏文件没变的不重装）。电脑上的盘游装不了，只提示。
- 激活包打包在压缩包里的（文件夹格式常见，比如双影奇境的压缩包里是 `PPSA08560/DLC/…pkg`），盘架只看得到分享里的文件，编排里写不进 `packages`，也不写说明。盘游装好、注册后在主机上的游戏目录里往下三层找 32 MB 以内的 `.pkg`，同样核对后复制到数据目录 `packages/` 再装（原文件名带 `[ ]` 之类，安装接口当 URI 解析会出错），记在 `console-packages.json`，详情页一起列出。核对不上的（游戏自己的数据文件碰巧叫 `.pkg`）不碰。以前装好的游戏，在「⋯」里点「注册到主机」时也会找一遍。
- 删掉主机上的游戏时包本身不卸：注销游戏时系统可能已经一起删了，留着也只占系统里一条记录。盘游只把这款游戏装过的包记成没装，再装游戏时重新装一遍，系统回「已经装过」时照样算装好。
- 已知限制：编排改了但压缩包没变时（比如只多了一个要拷的文件），已装好的游戏不会自动补上，要删掉重装。

### 反馈：`/盘游/反馈/<设备 ID>.json`

和评价一样每台设备写自己的、盘架读：

```json
{"version":1,"device":{"id":"…","name":"PS5"},"updated_at":1794470400,
 "items":[{"id":"9f2c…","title_id":"PPSA03016","format":"unknown","surl":"1AbCd","plan_rev":2,
           "kind":"mismatch","detail":"找不到 apr0.4.2.1/libSceAmpr.sprx","at":1794470000}]}
```

- `kind`：`mismatch`（网盘里的文件和编排对不上，自动）、`install_failed`（照编排装失败，自动，带失败原因）、`bad_review`（用户标了「有问题」，自动，带那句说明）、`manual`（详情页「⋯ › 让盘架重新分析」）。
- 盘架每 10 分钟读一次，`plan_rev` 不低于现在编排的就重新分析（反馈写进给模型的输入），发布 `rev` 更高的编排；比现在的低的说明已经分析过了，不再处理。处理过的记在 `feedback` 表，不重复处理。
- 盘游这边一条反馈留到资源库里这种格式的 `rev` 比它高（盘架已经重新分析过），或者 30 天，才从文件里去掉。不需要盘架另写回执。

## 不做

- 往主机上游戏目录以外的地方放文件、换挂载工具。
- 估解压后多大：要读压缩包里的文件头，等盘游装过一次再说。
- 盘游自己调大模型：密钥和分析都放在盘架。
