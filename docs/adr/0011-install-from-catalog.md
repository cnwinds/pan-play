# 0011 盘游列出全部游戏，点安装时自己转存，网盘只当缓存

状态：已接受（2026-11-11）

## 背景

原来的分工：盘架从资源站采集链接、把游戏转存进网盘；盘游只看网盘游戏库目录里有的游戏。想玩一个网盘里没有的游戏，要先去盘架点「加入网盘」，等转存完再回盘游安装；网盘满了还要回盘架「退出网盘」腾地方。用起来两边来回跑，而且要自己操心网盘里该放哪些游戏。

用户要的只是「装这个游戏」。网盘在中间只是中转：分享转存在百度服务器端完成，几秒钟，不占带宽；真正花时间的是下载。所以网盘里放哪些游戏应该由程序按需决定，对用户透明。

盘游登录本来就是网页版扫码，拿到的 BDUSS / STOKEN 和盘架一样，网页接口（bdstoken、建目录、移动、删除）也已经在用，转存需要的登录态是现成的。

## 决定

### 分工

- **盘架**：只做资源采集。抓帖子、挑格式（[0007](0007-game-format-variants.md)）、定期检查链接还能不能用、把资源目录发布到网盘。自动转存默认关掉；「加入网盘 / 退出网盘」留着当管理和排查工具。
- **盘游**：用户唯一的入口。列出资源目录里的全部游戏，点安装时自己转存，空间不够时自己把可以退的游戏移出网盘，然后照原来的流程安装。

两边仍然只通过同一个百度网盘账号交换数据（和 [0006](0006-sync-reviews-via-netdisk.md) 一样），装游戏时不需要电脑上的盘架开着。

### 资源目录：`/盘游/资源库.json`

盘架每次采集或检查完链接后，有变化就整份覆盖上传。只收有游戏编号、至少有一种能用格式的游戏（没编号的盘游不知道往哪放）。

```json
{"version":1,"generated_at":1794470400,"library_dir":"/游戏资源/PS5",
 "games":[{"title_id":"PPSA03210","concept_id":10001234,"name":"对马岛之魂","added_at":1794400000,
           "variants":[{"format":"exfat","surl":"1AbCd","pwd":"x1y2","version":"1.05","firmware":"4",
                        "size":52613349376,"alive":true,"checked_at":1794400000,
                        "review":{"playable":false,"note":"…"}}]}]}
```

- `format` 是 `exfat`、`folder`、`unknown`，对应网盘里的 `@exfat`、`@folder`、`@other`（0007）。PKG、单独的补丁 / DLC 不收，和盘架现在挑链接的规则一样。
- 同一个编号有几个帖子时合成一个游戏，`name` 取最新帖子的名字，`added_at` 是最新帖子被采集到的时间。每种格式只留一条链接：能用的优先，然后版本高的，再然后帖子新的。
- `size`、`alive`、`checked_at` 来自盘架最近一次列分享（每条链接 7 天复查一次）；没列过时 `size`、`checked_at` 为 0，不写 `alive`。确认失效的写 `alive: false`，仍然列出来，盘游显示「链接失效」。
- `review` 是盘架按 0006 把分享里的 `md5` 和评价对上的结果，对不上时不写。盘游不用自己再列分享算指纹，转存前就能提示「这份评过不能玩」。
- 游戏的资料（名字、封面、介绍）两边要显示得一样，以盘架查到的为准：
  - 这款游戏自己的商店页是空的，盘架借了资料库里同名游戏的商店页（名字和商店页上的对得上才借，免得借到合集）时，写 `store_concept_id`，盘游按它查商店。
  - 商店里没有这款游戏的介绍（下架了）时，写 `info`，内容是盘架从资源站帖子里取的 `{"cover":"https://…","description":"…","publisher":"…","release_date":"2021-08-17"}`，每项可能缺。盘游查商店也查不到时就显示这些，并注明介绍取自资源站帖子。介绍截到 1500 字。
- `library_dir` 是盘架的转存目录。两边必须是同一个目录，不然盘架转存的游戏盘游看不到，盘游转存的盘架也不认；所以和盘游设置里的游戏库目录不一样时，盘游设置页直接把游戏库目录填成 `library_dir`，保存后生效。

盘游启动时先用存在本机的那份（数据目录 `shelf-library.json`），之后每 30 分钟按 `fs_id` 看有没有变，变了再读；打开游戏库时超过 5 分钟没看过也看一次。设置页「游戏库目录」下面显示读到了几款、什么时候发布的。

### 游戏库：网盘里的 ∪ 资源目录里的

- 游戏库先列网盘游戏库目录里的，再列装在主机上、网盘里已经没有的，最后是资源目录里有、网盘里没有的（按盘架采集到的先后，新的在前）。按游戏编号合并。
- 网盘里没有的游戏路径按转存后会放的位置拼（`<游戏库目录>/<游戏编号>`），名字用资源目录里的（商店和资料库都没有时）。封面上的大小用资源目录里的，角标画虚线框。
- 详情页的格式里，网盘里没有的标「需转存」，盘架查过失效的标「链接失效」、安装按钮不能点。网盘里是没分格式的旧目录时不加资源目录的格式，照旧装网盘里那份。
- 安装队列照旧；只是安装网盘里没有的格式时，队列里先多一步「转存」，进度上显示正在核对链接、腾空间还是转存。

### 点安装之后

1. **核对链接**：验证提取码、列分享（接口和盘架 `server/baidu.mjs` 的 `listShare` 一样），拿到总大小。链接失效、提取码错时这一项失败，提示换别的格式；不自动换格式，格式是用户选的。
2. **腾空间**：见下一节。腾不出来就失败并说清楚差多少、哪些游戏是不能动的。
3. **转存**：转到 `<游戏库目录>/<游戏编号>/@<格式>`，流程照盘架的 `transferOne`（verify → 用网盘客户端 UA 打开 `/s/<surl>` 取 `bdstoken`、`shareid`、`share_uk` → `share/list` → `share/transfer`）。分享里只有一个外包目录时把里面的东西挪出来（盘架的 `flattenWrapper`）。
4. **安装**：和原来一样从网盘边下边解。

转存的坑都照盘架记过的处理：`surl` 去掉开头的 1 再 verify；`randsk` 已经是编码过的，不要再编码；返回「已存在」要列目录核实；文件数超过 `target_file_nums_limit` 时报错说明（非会员上限比会员低）。

### 网盘空间：游戏区有上限，只退能转回来的

设置的「网盘」里两个数：

- **游戏最多占用网盘**（游戏区上限），默认 2048 GB：游戏库目录里所有游戏加起来不超过它。游戏大小用 [0010](0010-shelf-sizes-in-background.md) 的容量缓存，没量过的当场量。
- **网盘至少留出**（保底），默认 200 GB：网盘总剩余低于它就不再转存，和盘架原来的保底线一样。查不到网盘空间时只按上限算。

转存前算一下：游戏区已用 + 这次大小 ≤ 上限，并且网盘剩余 − 这次大小 ≥ 保底。不满足就挑游戏移出网盘，直到满足。

**能退的**：同时满足

- 资源目录里有这个游戏的这种格式，并且退之前当场核对一次链接还能用（核对方法同上）。退掉以后随时能再转回来。
- 没有设备正在装它（见下面的「在用记录」），也不在本机的安装队列里，也不是这次要装的这款游戏。

自己放进网盘、资源目录里没有的，链接已经失效的，没分格式的旧目录，一律不退。一种格式退掉后游戏目录空了，游戏目录也删掉。

**先退哪些**：先退已经装在任何一台设备主机上的，然后是最久没用过的，同样时先退大的。「用过」指盘游转存或开始安装它的时间，各设备取最新的；都没有记录的当作最久没用过。

**删不掉时**：百度要求安全验证时 `remove_path` 会改成移进 `/盘游待删除`，这并不腾出空间。这种情况不算退成功，接着挑下一个；最后还腾不够时，安装失败的原因里说明还差多少，并提醒去网盘 App 里清空这个目录。

一次退出几个游戏、退的是哪些都写进日志（「为了装 X，移出网盘：A、B，腾出约 N GB」），腾的过程中安装进度上显示正在移出哪一款。

### 在用记录：`/盘游/在用/<设备 ID>.json`

和评价文件一样每台设备写自己的、读别人的，设备 ID 用评价同步那个。

```json
{"version":1,"device":{"id":"…","name":"PS5"},"updated_at":1794470400,
 "installing":[{"path":"/游戏资源/PS5/PPSA03210/@exfat","heartbeat":1794470400}],
 "installed":["/游戏资源/PS5/PPSA03210"],
 "used":{"/游戏资源/PS5/PPSA03210/@exfat":1794470000}}
```

- 开始安装时写入 `installing`，装的过程中每 5 分钟更新一次 `heartbeat`，装完或停下时去掉。`heartbeat` 超过 15 分钟没更新的当它已经停了。
- `installed` 是这台设备主机上装着的游戏目录（主机上一款游戏只装一种格式，按游戏算就够），取游戏库列表上次读到的安装情况。
- `used` 是开始安装（包括先转存的）的时间，本机的另存一份在数据目录 `drive-usage.json`，重启后还在。
- 有变化 3 秒后上传；装的时候每 5 分钟、平时每 6 小时也传一次。退游戏之前重新读一遍所有设备的文件。

## 不做

- 盘游自动换格式、换链接：格式是用户选的，失败了让用户自己挑。
- 根据热度提前转存：盘架自动转存关掉，先看按需转存要等多久再说。
- 资源目录里的补丁：盘架现在不收单独的补丁 / DLC 链接。资源站出了更高版本时，盘架挑链接会换成新版本，盘游以后可以据此提示「资源有新版本」，这次不做。
- 两台设备同时腾空间的严格互斥：在用记录能挡住「删掉别的设备正在装的」，两台同时为各自的安装挑同一个游戏退出这种情况很少，最坏是多退了一个，之后还能转回来。
- 安装前按「下载测速」的结果估下载要多久：以后再做。

## 影响

- 盘游新增：`pc/src/shelf_library.cpp`（读资源目录）、`shelf_transfer.cpp`（核对链接、腾空间、转存、去外包目录）、`drive_usage.cpp`（在用记录），自测在 `shelf_self_test.cpp`（内存里的假网盘）。`DrivePlugin` 加了 `list_share`、`transfer_share`、`move_path`、`quota`，目前只有百度实现。
- 盘架新增：`server/link-check.mjs`（链接每 7 天复查一次，列分享，顺便记下大小和 `md5`，评价比对也用得上）、`server/library-publish.mjs`（发布资源目录，每 10 分钟看一次有没有变）、`baidu.mjs` 的 `writeSmallFile`（和盘游 `write_small_file` 一样用 `d.pcs.baidu.com` 的 `upload`）。网盘页加了「盘游资源库」一栏。自动转存本来就默认关着，README 的定位改成「资源采集，平时不用管」。
- 网盘里的游戏可能随时被移出，所以「网盘里有」不再代表「用户想要」。盘架的「已入盘」状态只反映现在网盘里有什么，评价比对（0006）不受影响。
- 资源目录、在用记录的格式改动要两边一起改。
- 下载速度：非会员下载约 100 KB/s，50 GB 的游戏要四五天。按需转存只省掉了「先去盘架加入」这一步，下载本身要多久不变。
